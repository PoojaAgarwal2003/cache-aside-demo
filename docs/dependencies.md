# Dependency decision (2026-10-04)

Java **17 stays the language and runtime baseline**. The historical Boot 3.3.5
and Gradle 8.14.3 pins in the photographs are not the support decision.

Official information checked before implementation:

| Decision | Official source |
|---|---|
| Boot 4.1.1 is the project's current stable release; requires Java 17+ | [Project](https://spring.io/projects/spring-boot/), [system requirements](https://docs.spring.io/spring-boot/system-requirements.html) |
| Gradle 9.8.0 runs on Java 17 and is supported by Boot's 8.14+/9.x plugin | [Gradle compatibility](https://docs.gradle.org/current/userguide/compatibility.html), [Boot Gradle plugin](https://docs.spring.io/spring-boot/gradle-plugin/index.html) |
| Exact Gradle archive/wrapper hashes | [Release metadata](https://services.gradle.org/versions/current), [checksums](https://gradle.org/release-checksums/) |
| Resilience4j 2.4.0 restored Java 17 targeting and supports Boot 4 | [Release notes](https://github.com/resilience4j/resilience4j/releases/tag/v2.4.0), particularly PR 2415 |
| PostgreSQL 16.15 / Redis 7.4.11 official image tags | [PostgreSQL manifest](https://github.com/docker-library/official-images/blob/master/library/postgres), [Redis manifest](https://github.com/docker-library/official-images/blob/master/library/redis) |
| Exact Boot-managed dependency versions | [Boot 4.1.1 BOM](https://repo.maven.apache.org/maven2/org/springframework/boot/spring-boot-dependencies/4.1.1/spring-boot-dependencies-4.1.1.pom) |
| Testcontainers 2.0.5 | [Releases](https://github.com/testcontainers/testcontainers-java/releases), [BOM](https://repo.maven.apache.org/maven2/org/testcontainers/testcontainers-bom/2.0.5/testcontainers-bom-2.0.5.pom) |
| JUnit 5.14.4 retained as explicitly requested | [BOM](https://repo.maven.apache.org/maven2/org/junit/junit-bom/5.14.4/junit-bom-5.14.4.pom), [JUnit 5 guide](https://docs.junit.org/5.14.4/user-guide/) |

Boot 4 uses Jackson 3 and modular starters: use `spring-boot-starter-webmvc`
and `spring-boot-starter-flyway`, rather than assuming Boot 3 package locations.
Resilience4j core APIs avoid an unnecessary auto-configuration coupling.
Boot normally selects JUnit 6.0.3; the explicitly enforced JUnit 5 BOM retains
the requested framework, and compatibility must be demonstrated by actual tests.

**Observed compatibility boundary:** Spring 7's JUnit `SpringExtension` calls
JUnit 6's `ExtensionContext.Store.computeIfAbsent`; it fails with JUnit 5's
`NoSuchMethodError`. Integration tests therefore use JUnit 5's lifecycle to
start/close the real `SpringApplication` on a random loopback HTTP port. They
do not use `@SpringBootTest`/`SpringExtension` or substitute a mock server.
Spring Boot Test's managed test dependencies remain available. This deliberate
adaptation preserves both the maintained Spring release and the requested
JUnit 5/Java 17 baseline; the real-HTTP acceptance suite guards it.
The CI action consumes Adoptium's semantic version `17.0.20+101`, which maps
to the selected JDK's upstream version `17.0.20.1+1`; these are not two JDKs.

The native Gradle platform uses Boot's BOM for Hibernate, Flyway, JDBC,
Awaitility, Redis client and logging. PostgreSQL JDBC is an **implementation**
dependency so later LISTEN code can use `PGConnection`. `gradle.lockfile` is
generated by Gradle, not hand-authored. Container tags **and registry manifest
digests** are pinned in Compose. The exact PostgreSQL image is also pinned in
Testcontainers. Updates are deliberate future changes, not floating `latest`.

Maintenance describes upstream release selection, not production certification
or a promise of indefinite support. Recheck release/security information when
resuming future milestones.
